# Bhaumik Singh Chauhan — Freelance Portfolio

A fast, static site for freelance clients: services, case studies, a Giving Back page, resume and a contact form.
Built with [Astro](https://astro.build) and hosted free on [Netlify](https://www.netlify.com). There is no server to run or pay for.

## Run it locally

```sh
npm install
npm run dev        # http://localhost:4321/
npm run build      # type-check + production build into dist/
npm run preview    # serve the production build
```

Requires Node.js 22.12 or newer.

## Where to edit things

All text lives in a few data files. You rarely need to touch the components.

| What                                                    | File                                    |
| ------------------------------------------------------- | --------------------------------------- |
| Name, email, links, availability, hero text, bio        | `src/data/site.ts`                      |
| Services, pricing models, "what you can expect"         | `src/data/services.ts`                  |
| Work history                                            | `src/data/experience.ts`                |
| Skills, education, achievements, publication            | `src/data/skills.ts`, `education.ts`, `achievements.ts` |
| How-I-work steps, FAQ                                   | `src/data/process.ts`, `src/data/faq.ts` |
| Contact form budget / timeline options                  | `src/data/contact.ts`                   |
| Testimonials (section hidden while empty)               | `src/data/testimonials.ts`              |
| Case studies                                            | `src/content/work/*.md`                 |
| Giving Back page (name, story, promises, focus areas)   | `src/data/giving.ts`                    |
| Giving Back drives and their photos                     | `src/content/drives/*.md`               |
| Colours and fonts ("Copy Notebook" design)              | `src/styles/tokens.css`, `astro.config.mjs` |

Search the project for `PLACEHOLDER`: those lines are suggested wording to review and rewrite in your own words.

### Turn on the contact form

1. Go to [web3forms.com](https://web3forms.com), enter `bhaumiksingh10@gmail.com`, and copy the access key they email you.
2. Paste it into `web3forms.accessKey` in `src/data/site.ts`.

The key is public by design: it can only deliver messages to your inbox. Until it's set, the contact page shows email links instead of a form.

### Show or change your availability

In `src/data/site.ts`, set `availability.status` to `'open'`, `'limited'` or `'booked'`. The sticky notes on the home and contact pages and the call-to-action text update everywhere.
Optional extras in the same file: `whatsapp` (digits with country code, e.g. `919876543210`) and `calUrl` (a Cal.com or Calendly booking link). Each one stays hidden while empty.

### Add a case study

Copy any file in `src/content/work/`, rename it (the file name becomes the URL, e.g. `my-project.md` → `/work/my-project/`), and edit the frontmatter and the Problem / Solution / Outcome / Learnings sections. `featured: true` puts it on the home page; `order` sets its position.

### Add a Giving Back drive (with photos)

1. Copy `src/content/drives/2026-12-winter-clothes-drive.md` and rename it, e.g. `2027-01-blanket-drive.md`.
2. Put the drive's photos in the same folder (JPG or PNG, any size; the site shrinks them).
3. Fill in the frontmatter. Set `status: done`, then add `volunteers`, `result` and the photos:

   ```yaml
   photos:
     - src: ./blanket-drive-1.jpg
       alt: Friends packing blankets into bags
       caption: packing day!
   ```

The drive appears in the drive log, and its photos replace the empty polaroids on the Giving Back and home pages.
Only publish photos people agreed to. Never publish identifiable photos of children from shelters or rescue homes.

### Resume PDF

`resumeUrl` in `src/data/site.ts` points to the Google Drive copy. To host the PDF yourself, put it at `public/resume.pdf` and set `resumeUrl: '/resume.pdf'`.

### Social preview image and icons

`public/og/default.png`, `favicon.svg`, `favicon.ico` and `apple-touch-icon.png` are generated by `npm run og` (see `scripts/generate-og.mjs`). Re-run it if you change your name or headline there.

## Deploying (Netlify)

Netlify builds the site from this repository on every push to `main`, using the settings in `netlify.toml`
(`npm run build`, publish folder `dist`, Node 22).

- **A nicer free address:** in Netlify, go to **Site configuration → Change site name** and pick e.g. `bhaumikchauhan`. The site becomes `bhaumikchauhan.netlify.app`.
- **Netlify's free plan** has monthly limits on deploys and traffic. A personal site stays well within them; just don't redeploy dozens of times a day.

### Get found on Google

1. Open [Google Search Console](https://search.google.com/search-console) → **Add property** → **URL prefix**, and enter your Netlify address.
2. Choose the **HTML tag** method and copy only the code inside `content="..."`.
3. Paste it into `seo.googleVerification` in `src/data/site.ts`, push, wait for Netlify to deploy, then click **Verify**.
4. Under **Sitemaps**, submit `sitemap-index.xml`.
5. Link the site from your LinkedIn, GitHub profile and resume. Those links help Google trust it.

### Using your own domain later

No code changes needed. Buy the domain, then in Netlify go to **Domain management → Add a domain** and follow its DNS steps. HTTPS is free and automatic.
The site reads its address from Netlify at build time, so canonical links, the sitemap and social previews switch to the new domain on the next deploy.
Afterwards, add the new domain in Google Search Console too.

## Before going live

- Review every `PLACEHOLDER` (hero text, timelines, budgets, payment terms, FAQ answers).
- Your current employer and the WhatsApp platform's product name are intentionally not named. Keep it that way unless you're sure it's fine to share.
- Check your employment contract for side-work or IP clauses.
